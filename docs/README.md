# Standpoint — docs

Supporting documentation for [Standpoint](../README.md) (repo slug `freight-radar`).
The README is the front door; this directory holds the deeper engineering record.

- **[Architecture Decision Records](adr/)** — Nygard-format ADRs capturing the
  load-bearing decisions: static committed JSON over a live API, DuckDB as the
  single source of truth, deterministic template prose (no model in the number
  path), cutting the GDELT attention feed, Temporal-for-durability vs the Action
  as production driver, and the deck.gl-on-globe depth fix.
- **[Data Atlas](DATA-ATLAS.md)** (also as a [PDF](DATA-ATLAS.pdf), regenerated by
  `build_atlas_pdf.py`) — the free-data story: every source the app uses,
  categorized by tier, with how the layers connect.
- **[Feature ledger](FEATURES.md)** — the full feature inventory the README's
  short list summarizes: all four views, the detection spine, cross-domain
  signals, provenance surfaces, and the pipeline, with dated verification
  receipts.
- **[Build plans](plans/)** — every planning artifact, indexed one row per doc with
  a single true status. The **active plan** is
  [`plans/STANDPOINT-VISION.md`](plans/STANDPOINT-VISION.md) (P0–P3 shipped; P4–P6
  a capacity-bounded menu), with
  [`plans/HARDENING-PLAN.md`](plans/HARDENING-PLAN.md) **in progress** as the
  current work. The strategy satellites (the 5-year plan, the AI-native
  architecture) are labeled as such in the index.
- **[Writing](writing/)** — longer-form essays; currently
  ["Honesty as a compile error"](writing/honesty-as-a-compile-error.md), the
  honesty-harness writeup.

The architecture diagram (the IMF PortWatch backbone → ingest+detect → DuckDB →
publish → static JSON → React globe flow, driven by a Temporal workflow on a
Schedule) lives in the [main README](../README.md).

The image assets in this directory (`hero.png`, `flag-detail.png`,
`timescrubber.png`) are the README's screenshots.
